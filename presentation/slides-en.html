How Do We View the Book After Conversion?

"The book is data, not documents"

The content is broken down into 13 separate Markdown chapters, making it searchable, indexable, and buildable — all before the UI touches it.

What Are the Architectural Consequences?

  1. Deployable to any static host (no dynamic server needed).
  2. The client owns interactivity: search, bookmarks, and dark mode run in the browser.
  3. Build-time computation (SSG) eliminates runtime servers.

Why Did We Remove Authentication?

  • ❌ AuthProvider, middleware, and Supabase fully removed
  • 🎯 Scope discipline: a book read without accounts
  • 🔖 Local bookmarks (localStorage) instead of cloud sync
  • 🗂️ .env.local remnants: unused Supabase variables

Search Data Is Pre-Built

// scripts/build-search-index.mjs:8-14
function toSearchContent(raw) {
  return raw
    .split("\n")
    .filter(line => !line.startsWith("#") && !line.startsWith(">"))
    .join(" ")
    .replace(/\s+/g, " ")
    .trim();
}

Input: content/chapters/*.md

Process: Filter (#, >) ← Collapse spaces ← JSON

Output: public/search-data.json

Size: 1.75 MB / 13 documents

Cache: immutable, max-age=31536000

Note: shipped to every visitor (vs. server search)
