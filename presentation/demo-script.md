### شرح Hydration — النمط الخطأ مقابل النمط الآمن

> **هذا شرح مُكمّل لشريحة 24-27 في العرض التقديمي.**

**النمط الخطأ — يسبب mismatch:**
```tsx
// ❌ خطأ: قراءة localStorage أثناء الـ render
function ThemeToggle() {
  const isDark = localStorage.getItem("theme") === "dark";
  return <div>{isDark ? "🌙" : "☀️"}</div>;
}
```
المشكلة: الخادم يُرجع "☀️" (لا يوجد `localStorage` على الخادم)، والعميل يُرجع "🌙". يحدث `Hydration mismatch`.

**النمط الآمن — استخدام `suppressHydrationWarning` + `useSyncExternalStore`:**
1. **السكريبت البيني** (`app/layout.tsx:39-41`): يُنفذ قبل أن يرى React الصفحة، ويضيف `class="dark"` على `<html>` — نفس ما يفعله الخادم في `layout.tsx:37`.
2. **`suppressHydrationWarning`** (`app/layout.tsx:37`): يخبر React بتجاهل الفرق في `class` لأننا نعرف أننا نتحكم فيه.
3. **`useSyncExternalStore`** (`components/Navbar.tsx:20-24`): يقرأ الحالة من `document.documentElement.classList` بشكل آمن مع حفظ التزامن بين التبويبات.

**التيار الذي يُقال:**
> "النمط الآمن يتكون من ثلاثة طبقات: السكريبت البيني الذي يُنفذ قبل الرسم، و `suppressHydrationWarning` الذي يخبر React بالتجاهل، و `useSyncExternalStore` الذي يقرأ الحالة بشكل آمن. هذا هو النمط الموصى به في Next.js مع React 19."

## الخطوة 8 — PWA: وضع عدم الاتصال (9:00–11:00)

> ⚠️ **مهم جداً:** خدمة Service Worker معطّلّة في وضع التطوير (`next.config.ts:8` — `disable: process.env.NODE_ENV !== "production"`). يجب بناء المشروع وتشغيله كإصدار إنتاجي.

**الفعل:**
1. أوقف خادم التطوير (`Ctrl+C`).
2. شغّل أمر البناء (يتضمن `prebuild` تلقائياً):
   ```bash
   pnpm build
   ```
3. شغّل خادم الإنتاج:
   ```bash
   pnpm start
   ```
4. افتح `localhost:3000`.
5. افتح أدوات المطور (F12) → تبويس Application → Service Workers. تأكد أن `sw.js` مسجّل.
6. انتقل لصفحة فصل (مثلاً `/chapter/intro/`).
7. في تبويس Network، حدد "Offline" من القائمة المنسدلة.
8. حاول التنقل — الصفحة تظهر بشكل طبيعي من الكاش.

**التيار الذي يُقال:**
> "الآن في وضع الإنتاج: Serwist يُسجّل Service Worker الذي يخزن جميع الأصول الثابتة عبر `precacheEntries` في `sw.ts:6`. عند تفعيل وضع عدم الاتصال في DevTools، يتعامل `defaultCache` (`sw.ts:10`) مع طلبات التنقل والموارد. اللحظة الأولى قد تظهر شاشة تحميل، لكن بعدها تعمل الصفحات المخزنة بدون اتصال. نلاحظ أن `skipWaiting: true` و `clientsClaim: true` (`sw.ts:7-8`) يُنشّطان الـ SW فوراً بدون انتظار إغلاق التبويبات."

**الدليل:**
- `sw.ts:6-8` — إعداد Serwist مع precacheEntries و skipWaiting و clientsClaim.
- `next.config.ts:8` — `disable: process.env.NODE_ENV !== "production"`.

**ملاحظة:** إذا فُتحت صفحة لم تُخزَّن مسبقاً، قد تظهر صفحة خطأ. لا يوجد `setCatchHandler` في `sw.ts` — متوافق مع حقيقة أننا لا نقدم صفحة fallback مخصصة.
