01

ما فكرة المشروع؟

بصائر منصة قراءة رقمية للكتاب العربي «بصائر في الكون والحياة والدين» للدكتور هيثم طلعت. الهدف هو تقديم الكتاب كتجربة ويب مريحة، بدلاً من حصره في ملف PDF طويل يصعب التنقل والبحث داخله.

المشكلة التي يعالجها

الكتاب الطويل يجعل الوصول إلى فصل أو فكرة محددة والعودة إلى موضع القراءة أمراً أقل سهولة، خصوصاً على الهاتف.

الحل الذي يقدمه

تقسيم المحتوى إلى فصول قابلة للتصفح والبحث، مع أدوات تساعد القارئ على حفظ ما يهمه ومتابعة قراءته.

02

ماذا يستطيع القارئ أن يفعل؟

هذه هي الوظائف الأساسية كما يصفها المستودع. تخيّلها من منظور شخص يفتح الموقع ويريد قراءة الكتاب.

📚قراءة الفصول

المحتوى مقسّم إلى ملفات Markdown بدلاً من صفحة PDF واحدة. يمكن فتح كل فصل والتنقل بين الفصول المتتابعة.

🔎البحث النصي

البحث في نصوص الفصول باستخدام FlexSearch. يراعي البحث اختلافات شائعة في كتابة العربية مثل التشكيل وبعض أشكال الحروف.

🔖الإشارات المرجعية

يمكن حفظ الفصول المهمة والعودة إليها لاحقاً. تُخزّن العلامات في localStorage على جهاز القارئ.

🌗الوضع الفاتح والداكن

تبديل مظهر القراءة لتقليل إجهاد العين وتوفير تجربة مناسبة لتفضيلات المستخدم.

🧭التنقل داخل الكتاب

قائمة جانبية للفصول، وروابط للفصل السابق والتالي، لتسهيل الانتقال دون العودة إلى البداية.

📱التصميم المتجاوب

تتكيف الواجهة مع شاشات الحاسوب والهواتف، مع مراعاة اتجاه الكتابة من اليمين إلى اليسار.

03

كيف يعمل المشروع؟

لفهم التطبيق، افصل بين المحتوى (نص الكتاب) والواجهة (ما يراه القارئ) والأدوات التي تربطهما.

1. ملفات المحتوىفصول عربية مكتوبة بصيغة Markdown داخل content/chapters.
←
2. طبقة القراءةأدوات في lib لتحميل الفصل وتجهيزه للعرض.
←
3. واجهة Next.jsصفحات ومكوّنات React تعرض الفصول وأدوات القراءة.
←
4. المتصفحالقارئ يتصفح ويحفظ العلامات ويبحث محلياً.

ما Markdown؟

صيغة نصية بسيطة لكتابة العناوين والفقرات والقوائم والاقتباسات. تخزين الكتاب بهذه الصيغة يجعل المحتوى أسهل في التنظيم والتحرير والتحويل.

ما React وNext.js؟

React لبناء الواجهة من مكوّنات صغيرة قابلة لإعادة الاستخدام. Next.js إطار ينظم الصفحات والتنقل والبناء والتصدير.

ما localStorage؟

مساحة تخزين داخل المتصفح تحفظ بيانات بسيطة على الجهاز، مثل قائمة الفصول المحفوظة، دون الحاجة إلى حساب مستخدم أو قاعدة بيانات.

ما فهرس البحث؟

بيانات مجهزة لتسريع العثور على الكلمات داخل النصوص. يُنشأ ملف بيانات البحث أثناء مراحل ما قبل التشغيل أو البناء، ثم يُستخدم FlexSearch في المتصفح.

تدفق البحث باختصار: تُجمع نصوص الفصول في ملف بيانات بحث مُولّد، وعندما يفتح المستخدم نافذة البحث يُبنى فهرس FlexSearch في جهة العميل. بعد ذلك تُطبّع عبارة البحث العربية لتقليل أثر التشكيل واختلاف بعض الحروف، ثم تُعرض النتائج.

05

التعرّف إلى مجلدات المشروع

لا تحتاج إلى فهم كل ملف في البداية. ابدأ بالمجلدات التي تمثل أجزاء التطبيق الأساسية، ثم انتقل إلى ملفات الإعداد والأدوات عند الحاجة.

bassaer/ ├── app/ # صفحات Next.js والتخطيط العام ├── components/ # مكوّنات الواجهة مثل البحث والقائمة الجانبية ├── content/ │ └── chapters/ # نصوص فصول الكتاب بصيغة Markdown ├── lib/ # منطق التطبيق والأدوات المساعدة ├── public/ # الصور والملفات الثابتة وملفات PWA ├── scripts/ # سكربتات تجهيز المحتوى وفهرس البحث ├── docs/ # وثائق وملاحظات المشروع ├── e2e/ # اختبارات تجربة المستخدم من البداية للنهاية ├── presentation/ # ملفات/مواد مرتبطة بالعرض التقديمي ├── package.json # الاعتماديات والأوامر المتاحة ├── next.config.ts # إعدادات Next.js ├── tsconfig.json # إعدادات TypeScript ├── pnpm-lock.yaml # نسخ الاعتماديات المثبتة └── AGENTS.md # إرشادات العمل لوكلاء البرمجة
ملاحظة: هذا وصف للمجلدات الرئيسية الظاهرة في المستودع. قد تتغير الملفات أو تتوسع المجلدات مع تطور المشروع؛ افحص محتوياتها الفعلية قبل تعديلها.

app/ مقابل components/

المجلد الأول ينظم الصفحات ومساراتها، أما الثاني فيحتوي أجزاء واجهة يمكن استخدامها داخل أكثر من صفحة.

lib/ مقابل scripts/

lib يحتوي منطقاً تستخدمه واجهة التطبيق أثناء عملها. scripts يحتوي برامج مساعدة تُشغّل في مهام مثل تجهيز بيانات البحث.

06

تشغيل المشروع محلياً

المتطلبات الأساسية: Git وNode.js بإصدار متوافق مع المشروع وpnpm. استخدم الطرفية داخل مجلد العمل.

1. استنساخ المستودع

git clone https://github.com/islamux/bassaer.git cd bassaer

2. تثبيت الاعتماديات

pnpm install

3. تشغيل خادم التطوير

pnpm dev

افتح المتصفح على http://localhost:3000.

تنبيه: لا تعدّل ملفات المحتوى أو إعدادات البناء لمجرد التجربة. ابدأ بتشغيل المشروع واستكشافه، ثم افهم الملف المسؤول عن الميزة قبل تغيير الكود.
07

كيف يتم بناء الموقع ونشره؟

المشروع مضبوط على التصدير الثابت (Static Export). هذا يعني أن عملية البناء تنتج ملفات HTML وCSS وJavaScript وموارد ثابتة يمكن تقديمها من استضافة ملفات عادية.

# تثبيت الحزم pnpm install # بناء نسخة الإنتاج pnpm build

وفق إعدادات المشروع، ينتج البناء مجلد out/. تُرفع محتوياته إلى الاستضافة الثابتة. لا تحتاج الاستضافة إلى تشغيل خادم Next.js وقت تقديم الموقع.

ما المقصود بـ Static Export؟

بدلاً من إنشاء الصفحات على خادم عند كل طلب، تُجهّز ملفات الموقع مسبقاً أثناء البناء، ثم يرسلها خادم الويب إلى الزائر.

ما فائدة ذلك؟

استضافة أبسط، ومتطلبات تشغيل أقل، وإمكانية نشر الموقع على خدمات استضافة الملفات الثابتة.

08

مسار مقترح لفهم المشروع كمبتدئ

لا تحاول قراءة المستودع كله دفعة واحدة. اتبع هذا الترتيب، وشغّل التطبيق بعد كل مرحلة لتربط ما تقرؤه بما تراه.

المرحلة الأولى — شاهد التطبيق

شغّل المشروع، افتح عدة فصول، جرّب البحث والإشارات المرجعية والوضع الداكن. دوّن ما يحدث عند كل تفاعل.

المرحلة الثانية — افهم الصفحات

ابدأ من ملفات app/ لتعرف كيف تُبنى الصفحة الرئيسية وصفحة الفصل، وما التخطيط المشترك بينهما.

المرحلة الثالثة — افهم المكوّنات

افتح components/ وابحث عن المكوّنات التي شاهدتها في الواجهة، مثل شريط التنقل والقائمة والبحث.

المرحلة الرابعة — تتبّع البيانات

افحص content/chapters/ ثم lib/ لتفهم كيف ينتقل نص الفصل من ملف Markdown إلى واجهة القراءة.

المرحلة الخامسة — افهم البحث

اقرأ سكربت إنشاء بيانات البحث ثم منطق البحث في lib/ ومكوّن نافذة البحث.

المرحلة السادسة — اختبر تغييراً صغيراً

نفّذ تعديلاً بصرياً محدوداً، شغّل الفحوصات المناسبة، وتأكد من أن القراءة والبحث والتنقل لم تتأثر.
